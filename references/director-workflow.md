# 制作流程

## 1. 需求与证据

明确一句传播命题、观众、主体、真实内容、目标时长、画幅、音轨和素材。缺少非关键项说明假设；品牌截图、确切文案、必须对齐的声音不能伪造。按 assets/templates/brief.json 创建项目。先检查项目自己的 AGENTS.md。

## 2. 方案与路由

用 Router 获取已确认候选，再由内容语义决定表现：分类可以展开、比较可以并置、流程可以连续推进，不默认都变成卡片。

新任务两个方案即可，包含效果、分项时间区间和一个推荐理由；默认不向用户列技术名词。已授权直接做则简短展示后按推荐方向继续，不再索要同一授权。仅规划任务停在指定阶段。

没有已确认能力时可以由 Codex 通用实现完成项目，不把待确认 Skill 隐式当作自有库，也不为填库阻塞已有制作授权。新 Skill 学习请求则先完成具体候选，等待确认后整理入库。

估时区分设计、开发、渲染；默认简单2–5/3–10/1–5分钟，中等5–12/10–25/3–15分钟，复杂15–30/35–90/10–60分钟。数值只为20秒左右、素材齐全的起调范围，随镜头数和新能力验证量重估。不要把三阶段重叠工作错误相加为保证完成时间。

## 3. 分镜与时间轴

每镜一个信息任务，记录 message/hero/source_assets/visible_text/camera/motion/start_state/end_state。使用秒作为创作单位，渲染时按锁定帧率取整。长口播先整片视觉总表再局部动效，阅读帧相机稳定。连续镜头继承姿态和速度，防止每段重新起步。

选一个主工作流，专项能力解决缺口；Remotion组织时间轴、Three.js处理真实空间、SVG/Canvas处理图形等可组合但不可混为工具等价。检查具体引擎依赖和版本后再实现，不默认安装。

## 4. 实现与预览

内容、时间轴和运动参数分开。优先利用可靠原实现；移植只针对明确复用价值的机制，保留来源与差异。关键帧预览 → 最难转场短片 → 完整低成本预览 → 最终规格渲染。低清预览不修改最终 brief.spec。

## 5. 恢复与交付

每阶段更新 state.next_action、已选方案、授权、产物。恢复时 project-show 检查 brief 是否变化，读取当前分镜与文件，不从上次聊天推测。工程保留旧版，修改只作用相关镜头。

交付 MP4、可编辑 source、规格和限制。质量依据见 quality-gates.md；项目完成前必须真的完整解码并观看检查。有声音则监听和检查同步。知识学习是独立分支，满意、制作成功或“最终版”文件名均不等于允许永久保存。
