# 新 Skill 学习

1. scan发现新文件/版本。候选仅包含描述推断，不能直接确认入库。
2. inspect获取入口、文件清单和来源版本，读取该工作流实际需要的references/scripts；截断部分要补读。了解是否联网、付费、写记忆、复制素材或依赖本机工程，不执行这些操作。
3. 提炼三层：设计目的和动效规律；原工具的方法；运行条件与限制。原文支持与自己的推断分开。
4. search已确认能力，列出新增/重叠/冲突。相似命名不等于相同能力；不同工具的实现应作为同一模式的不同实现关联，而非静默覆盖。
5. 按skill-contract生成analysis JSON并analyze。仅阅读时verification=read。Skill的分析与其中可复用Pattern需要分别确认；不要把一个工具的所有审美偏好都默认变成用户偏好。
6. review呈现精确确认摘要。用户可全部、部分或不保存。部分确认时拆分，避免把未同意内容藏进附带字段。
7. 收到确认后approve对应ID，report汇总：新增能力、适用场景、接入方式、关联、限制、验证状态。无需让用户记关键词。

用户提供网页/GitHub链接：先阅读真实文件和必要资源；如需下载代码，按用户授权范围暂存后扫描。不能用README营销描述代替实现验证，不能在扫描时运行install脚本。初期不提供后台自动学习服务；在Director启动/恢复时自动执行发现与相关分析。

版本变动：全体文本、代码、配置的内容清单哈希变化即新候选；大型媒体不参与源码哈希，引用媒体的验证需独立记录文件哈希。更新候选只显示变化，对旧记录保留审计，不继承旧运行证据。

暂不保存的同版本不会反复提示；需要重新考虑时用原分析建立新proposal。正式库不自动接收扫描结果。
